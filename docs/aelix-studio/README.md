# Aelix Studio development

Aelix Studio is independently maintained and derived from [AionUi](https://github.com/iOfficeAI/AionUi).
Its repository policy is standalone operation with a small, reviewed downstream patch set.
Baseline: **v2.2.2**, commit `6744099b279b991c17e31c243f0920477bd31cb6`, unchanged
AionCore **v0.2.2**. See [upstream.json](upstream.json) for provenance.

## Included changes

- Aelix Studio name and Aelix mark in the shell, login, app and PWA icons.
- App ID `ai.aelix.studio`, protocol `aelix-studio://`, independent GitHub update
  feed at `handochan/aelix-studio`. Manual update manifests and downloads also use
  this repository. Publishing a release remains a separate, explicit operation.
- Production data uses Aelix Studio's Electron userData directory; development
  uses `Aelix Studio-Dev` (`-2` for the second instance). The Node host fallback
  uses `~/.aelix-studio-server`; no AionUi database migration is performed.
- Coding and Analytics are registered through the existing Custom Agent API and its generated assistant catalog
  before the first desktop window. Fresh chats prefer Aelix, while saved choices
  and disabled presets take precedence. Repeated startup refreshes the owned
  command path after an app move without replacing unrelated custom agents.
  Unchanged entries are not rewritten. Team support uses the existing backend's
  MCP/CLI transport selection, with `supports_team` enabled for both owned profiles.
- Bundled Python **3.12.12**, Aelix **0.1.0b2**, ACP **0.1.0**. The adapter is pinned
  to an immutable commit and archive checksum in `scripts/aelix-studio/runtime.json`.
  Dependencies are version/hash locked in `requirements.lock`. No system Python,
  uv, pip, ACP source checkout, or install-time package download is needed to run.
- Analytics **0.26.0** is built from a checksum-pinned source archive. Its upstream
  isolated-project contract is preserved: bundled uv **0.11.19** and the locked
  cache create each project's own environment rather than importing host libraries.
  Cache writes go to app data, not the signed application bundle.

Existing Aelix provider authentication and model settings are still read by Aelix;
the application does not ship API keys. Model access requires the configured
provider/local model. Runtime bundling alone does not make an internet provider
available in a closed network. Windows, Linux, macOS, single-operator WebUI, Coding,
Analytics and agent teams are release requirements. Corporate IdP SSO is deferred.

## Build and run

Use Node 22–24, Bun, build-time Python 3.9+, and uv. The prepared local checkout
has verified Node 24.22.1/Bun 1.4.4 under `.local/toolchains/` (see upstream.json).
The local wrapper uses those tools and selects the pinned backend for dev startup.

```sh
scripts/aelix-studio/run.sh install --frozen-lockfile
scripts/aelix-studio/run.sh run studio:runtime
scripts/aelix-studio/run.sh run dev
# Host-native installer/distribution build; prepares Aelix and upstream backend:
scripts/aelix-studio/run.sh run studio:dist
```

On another checkout use `bun` directly with the compatible toolchain. For dev,
first run `node scripts/prepareAioncore.js` and set `AIONUI_BACKEND_BIN` to its
prepared binary (or use the local wrapper). `bun run package` builds application
JavaScript; it does not produce an installer. `studio:dist` performs the native
runtime preparation and distribution build. `afterPack` rejects a missing runtime.
Cross compilation is intentionally unsupported for the Python bundle: build on
each target host. macOS arm64 is the accepted target; macOS x64/Linux have native
build paths; see the updated verification record for local container evidence. Windows x64 has a native build/permission transport and installer CI path; actual Windows acceptance is pending.

The Custom Agent API in AionCore v0.2.2 splits executable names on whitespace.
Studio therefore registers `node` with a `launch.cjs` argument: the unchanged
backend resolves its bundled Node, and the bridge starts bundled Python with
`spawn(..., { shell: false, stdio: 'inherit' })`. No system Node, command shell,
Git Bash or shell quoting is required, including paths with spaces/non-ASCII text.

Generated runtimes stay in `resources/bundled-aelix/<platform>-<arch>` and ship
outside ASAR. `manifest.json` records resolved versions, uv version and lock hash;
`checksums.json` inventories generated bytes. Python and wheel license files are
retained. No generated binaries, user state, transcripts or credentials enter Git.
The managed Python archive is verified by uv's embedded download checksums; it is
not a bit-for-bit reproducible build across different uv releases.

## Upstream tracking and delivery

- `origin`: `handochan/aelix-studio`, the canonical Studio repository. `upstream`:
  `iOfficeAI/AionUi`, with push disabled. This Git remote works with a standalone
  repository and does not require GitHub's fork network.
- Preserve the original Git commit history. Repository independence changes
  hosting metadata; the product's AionUi source provenance remains explicit.
  The live GitHub `fork` flag must be checked separately before claiming that
  the repository has been detached. A branch push does not imply a main merge.
- [upstream.json](upstream.json) records the source repository, Apache-2.0 license,
  adopted tag/SHA and chronological adoption history. Its last history entry must
  match the current pin. Studio app, Aelix runtime and AionCore versions are
  separate records; changing one does not advance the others.
- `node scripts/aelix-studio/checkUpstream.mjs` compares the latest stable release
  and its resolved commit with the pin, including annotated tags. It emits source
  links, adoption history and a compare URL. `current` means the tag and SHA both
  match; `review_required` includes a changed SHA under an existing tag.
  Network, API and invalid-metadata failures emit `error` and exit 1.
  `--fail-on-drift` exits 2 for a review requirement.
- The manual/PR workflow and relevant `main` pushes upload the JSON report.
  There is no schedule or automatic merge. The workflow must be on the default
  branch for manual dispatch; a local workflow change does not establish that
  remote tracking is active. The checker is maintainer tooling, not application
  telemetry or an automatic update check in closed-network deployments.

### Adopting an upstream release

1. Run the checker and review the release notes and source comparison. Fetch
   upstream tags into a separate namespace so they cannot replace Studio tags:

   ```sh
   # Once per fresh clone; existing checkouts already have this remote.
   git remote add upstream https://github.com/iOfficeAI/AionUi.git
   git remote set-url --push upstream DISABLED
   git fetch --no-tags upstream '+refs/tags/*:refs/upstream-tags/aionui/*'
   git rev-parse 'refs/upstream-tags/aionui/vX.Y.Z^{commit}'
   ```

   Compare the resolved SHA with the report. A moved tag requires investigation;
   never refresh the pin merely to make a check pass.

2. Create a review branch from Studio `main` and merge the verified upstream
   commit, retaining its ancestry. Resolve conflicts while preserving Studio
   branding, runtime integration, authentication and offline behavior. Keep the
   pinned AionCore binary unchanged unless its upgrade is explicitly reviewed.
3. In the same change, update the pinned tag/SHA and append a `method: "merge"`
   entry to `upstream.history`, describing the adoption. Update baseline mentions
   in both READMEs and NOTICE. Earlier history entries remain intact.
4. Validate the affected behavior and required repository checks on the proposed
   head. Record the source comparison, conflicts, validation and deferred changes
   in the PR. Merge and publish releases through their own delivery gates.

Individual backports retain the full-release baseline. Record their source in
the commit body with `Upstream-Repository: iOfficeAI/AionUi` and
`Upstream-Commit: <full SHA>` so they remain traceable without claiming adoption
of an entire release.

## Aelix brand preservation

The home header displays the official `lockup-light.svg` or `lockup-dark.svg`
according to the active theme. These contain both the mark and the original
Aelix wordmark, with their supplied geometry and spacing. The compact header
uses the official `mark.svg` alone. There is no additional typeset brand name.
All SVG files are copied byte-for-byte from the canonical source; no custom
badge, backplate, recoloring, skew, crop, or effects are applied.

Canonical source: [aelix-ai/docs/assets/brand](https://github.com/handochan/aelix-ai/tree/7d0a2c0f74c542492f65f3a43965452c4333b8e6/docs/assets/brand).
Follow its `BRAND.md`; preserve the supplied mark and wordmark geometry.
Source Git blobs:

- `mark.svg`: `4973c209e572fcf4c52b0f3ece20689d455aeedc`
- `lockup-light.svg`: `5c8da8643f1352236ab9c18a892c4ff362fce3ea`
- `lockup-dark.svg`: `97d7e456f69c6f134206b0e2db500cab50c4d19b`

Raster application/PWA assets remain proportional renders of the official mark.
